## 2. 📊 인프라 & 운영: "서버 모니터링 분석 가이드" (99 Points 화제작) {: #section-2 }

이번 주 긱뉴스에서 99개의 추천을 받으며 압도적인 1위를 기록한 글은 **kciter 님의 '서버 모니터링 분석 가이드'**였습니다.

### 2.1 대시보드 설치를 넘어 그래프를 읽는 3가지 기본 축 {: #section-2-1 }
대다수의 모니터링 튜토리얼은 그라파나나 데이터독을 설치하는 법만 알려줄 뿐, 정작 수많은 그래프 중 무엇을 보고 어떻게 판단해야 하는지 알려주지 않습니다.
* **사용률(Utilization)**: 자원이 얼마나 바쁘게 일하고 있는가? (CPU, 디스크 I/O)
* **포화도(Saturation)**: 처리하지 못하고 큐(대기열)에 쌓인 작업이 얼마나 있는가? (Load Average, Connection Backlog)
* **에러(Errors)**: 거절되거나 실패한 요청은 몇 개인가? (HTTP 5xx, 패킷 드롭)

### 2.2 CPU iowait, 메모리 가용량, 로드 애버리지 해석법 {: #section-2-2 }
* **CPU % vs iowait**: CPU 사용률이 100%가 아니더라도 `iowait` 수치가 치솟는다면 연산 파워 부족이 아니라 디스크/DB 병목입니다.
* **Load Average**: CPU 코어 수 대비 1분/5분/15분 로드 애버리지를 비교하여 트래픽 스파이크인지, 지속적인 자원 고갈인지 판별합니다.
* **메모리 Buffer/Cache와 Available**: 리눅스에서 Free 메모리가 0에 가깝다고 패닉에 빠질 필요가 없으며, OS가 캐시를 반환해 프로세스에 할당 가능한 **`Available` 메모리**를 지표로 삼아야 합니다.

## 3. 🧠 엔지니어링 위기와 리더십: "문제는 AI 코드가 아니라 아무도 모른다는 것" {: #section-3 }

### 3.1 AI 슬롭(Slop)과 아키텍처 이해도의 실종 {: #section-3-1 }
* **화두**: AI가 짠 코드의 성능이나 버그보다 더 근본적인 문제는, **"이제 팀 안에 그 코드가 왜 그렇게 작성되었는지, 시스템 경계가 어떻게 맞물려 있는지 아는 사람이 아무도 없다"**는 현상입니다.
* 팀원 모두가 질문을 Claude나 GPT에게만 던지다 보니 코드베이스는 빠르게 비대해지지만, 시스템을 조망하고 근본적인 리팩토링이나 장애 대응을 지휘할 수 있는 인간의 멘탈 모델이 무너지는 '지식 공동화(Brain Drain)'가 지적되었습니다.

### 3.2 스태프 엔지니어를 위한 일감 발굴과 시스템 거버넌스 {: #section-3-2 }
* 상명하달식 태스크에 의존하지 않는 스태프 엔지니어(Staff Engineer)는 **시스템의 병목, 팀 간의 마찰 비용, 방치된 기술 부채**를 능동적으로 발굴해야 합니다.
* AI가 쏟아내는 수많은 PR 속에서 전체 아키텍처의 일관성을 유지하고, 팀의 이해도를 유지하는 '기술 거버넌스'의 중요성이 다시 부각되었습니다.

## 4. ⚡ 아키텍처 & 차세대 툴체인 {: #section-4 }

### 4.1 브라우저 실시간 통신 설계: 무조건 WebSocket이 정답일까? {: #section-4-1 }
실시간 요구사항이 들어왔을 때 무작정 WebSocket부터 도입하면 연결 상태 관리, 재연결 백오프, 로드밸런서의 스테이트풀 세션 유지로 인해 인프라 복잡도가 폭증합니다.
* **SSE (Server-Sent Events)**: 작업 완료 알림, LLM 스트리밍, 대시보드 갱신 등 서버에서 클라이언트로의 단방향 데이터 전달에는 표준 HTTP 기반의 SSE가 훨씬 가볍고 방화벽 친화적입니다.
* **폴링(Polling) / 롱폴링**: 빈도가 낮거나 상태 복구가 중요한 작업에는 짧은 간격의 지능형 폴링이 운영상 가장 안전한 선택일 수 있습니다.

### 4.2 Cloudflare 에이전트 전용 CLI 'cf'와 올인원 임베디드 'LatticeDB' {: #section-4-2 }
* **`cf` CLI**: Cloudflare가 공개한 신규 CLI로, 기존 Wrangler 수준을 넘어 **3,000개 이상의 전체 Cloudflare API를 단일 CLI에서 처리**할 수 있도록 설계되어 AI 에이전트가 인프라를 자율적으로 배포/조작하는 표준 도구로 부상했습니다.
* **`LatticeDB`**: 데이터 간의 **관계 그래프 탐색, 벡터 임베딩 유사도 검색, 전문(Full-Text) 검색**을 별도의 서버 없이 단 하나의 로컬 임베디드 파일에서 처리하는 올인원 DB가 공개되어 로컬 AI 에이전트 개발자들의 큰 관심을 받았습니다.
